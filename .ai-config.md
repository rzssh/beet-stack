# AI Coding Assistant Configuration

This file contains coding standards and guidelines for AI assistants working on this codebase.

## Quick Reference

### Critical Rules
1. **Imports**: Always use `~/` absolute imports, never relative imports
2. **Nullish Coalescing**: Use `??` instead of `||` for null/undefined checking
3. **Logging**: Backend only - use `import { logger } from "~/core/logger"` 
4. **Errors**: Backend only - use structured error classes from `~/core/errors`
5. **TypeScript**: Prefer type guards over type assertions

## Import Patterns

### ✅ Correct Imports
```typescript
// Backend
import { logger } from "~/core/logger";
import { AppError, NotFoundError } from "~/core/errors";
import { auth } from "~/lib/auth-server";

// Frontend  
import { Button } from "~/components/ui/button";
import { authClientRepo } from "~/lib/better-auth/auth-client-repo";
import { getSessionFn } from "~/lib/better-auth/auth-session";
```

### ❌ Avoid These Imports
```typescript
// Don't use relative imports
import { logger } from "../core/logger";
import { Button } from "../../components/ui/button";

// Don't use src/ prefix on frontend
import { Button } from "src/components/ui/button";
```

## Operators & Syntax

### Nullish Coalescing (`??`) vs Logical OR (`||`)

**Use `??` for null/undefined fallbacks:**
```typescript
// ✅ Correct - only null/undefined trigger fallback
const timeout = config.timeout ?? 5000;
const name = user.name ?? "Anonymous";
const id = headers.get('x-request-id') ?? crypto.randomUUID();

// ❌ Wrong - 0, false, "" also trigger fallback  
const timeout = config.timeout || 5000; // breaks if timeout is 0
const name = user.name || "Anonymous"; // breaks if name is ""
```

**Use `||` only when you want falsy fallbacks:**
```typescript
// ✅ OK - when you want falsy values to fallback
const enabled = userSetting || defaultSetting; // false -> true
const message = customMessage || "Default message"; // "" -> "Default message"
```

## Backend-Specific Rules

### Logging
```typescript
// ✅ Correct
import { logger } from "~/core/logger";

logger.info("Operation completed", { userId, duration });
logger.warn("Slow query detected", { query, duration: 2000 });
logger.error({ error, requestId }, "Failed to process request");

// ❌ Never use console
console.log("Something happened"); // Never do this
console.error(error); // Never do this
```

### Error Handling
```typescript
// ✅ Correct - structured errors
import { NotFoundError, ValidationError, AuthorizationError } from "~/core/errors";

throw new NotFoundError("User", { userId });
throw new ValidationError("Invalid email format", { email, field: "email" });
throw new AuthorizationError("Insufficient permissions", { userId, action: "delete" });

// ❌ Wrong - generic errors
throw new Error("User not found");
throw new Error("Validation failed");
```

## Frontend-Specific Rules

### Session Management
```typescript
// ✅ Correct - for route loaders (server-side)
import { getSessionFn } from "~/lib/better-auth/auth-session";
const session = await getSessionFn();

// ✅ Correct - for components (client-side)
import { authClientRepo } from "~/lib/better-auth/auth-client-repo";
const { data: session } = authClientRepo.useSession();

// ✅ Correct - for mutations
await authClientRepo.signOut();
```

## TypeScript Best Practices

### Type Guards vs Type Assertions
```typescript
// ✅ Correct - type guards
if (typeof error === 'object' && error && 'message' in error) {
  logger.error(error.message);
}

if ('code' in error && error.code === 'VALIDATION') {
  // Handle validation error
}

// ❌ Avoid - type assertions
const message = (error as Error).message;
const code = (error as any).code;
```

### Optional Chaining
```typescript
// ✅ Correct - extensive optional chaining
const email = user?.profile?.email ?? "No email";
const count = response?.data?.items?.length ?? 0;
const setting = config?.features?.analytics?.enabled ?? false;

// ❌ Verbose - manual null checking
const email = user && user.profile && user.profile.email ? user.profile.email : "No email";
```

## File Naming & Organization

- **Files**: `kebab-case.ts` 
- **Directories**: `kebab-case/`
- **Components**: `PascalCase.tsx` but file named `component-name.tsx`
- **No underscore folders**: Use `core/` not `_core/`

## Common Patterns

### API Error Handling (Backend)
```typescript
// ✅ Service layer throws structured errors
async getUser(id: string) {
  const user = await db.findUser(id);
  if (!user) {
    throw new NotFoundError("User", { userId: id });
  }
  return user;
}

// ✅ Route handler lets error middleware handle it
app.get("/users/:id", async ({ params }) => {
  const user = await userService.getUser(params.id);
  return { user };
}); // No try/catch needed - error middleware handles it
```

### Component Props (Frontend)
```typescript
// ✅ Correct - use loader data when available
function Dashboard() {
  const { user } = Route.useLoaderData(); // From route loader
  // NOT: const { data: session } = authClientRepo.useSession();
}

// ✅ Correct - use hooks when loader data not available  
function NavigationComponent() {
  const { data: session } = authClientRepo.useSession();
  const user = session?.user;
}
```

This configuration helps maintain consistency and prevent common mistakes across the codebase.
